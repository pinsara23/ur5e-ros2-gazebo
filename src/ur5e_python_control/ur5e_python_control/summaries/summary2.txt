PROJECT GOAL
------------

The goal of this project is to learn ROS 2 robotics by controlling
an existing Universal Robots UR5e robot in simulation.

I do NOT want to build the robot model from scratch.

The planned final system is:

    Python
       |
       v
    ROS 2
       |
       v
    ros2_control
       |
       v
    UR5e
       |
       v
    Gazebo

Eventually I want to use MoveIt 2, control the robot using XYZ
coordinates, perform pick-and-place tasks, and potentially integrate
computer vision / AI.

ROS 2 ACTIONS
============================================================

We checked available actions with:

    ros2 action list

The important action was:

    /scaled_joint_trajectory_controller/follow_joint_trajectory

Then we checked it using:

    ros2 action info /scaled_joint_trajectory_controller/follow_joint_trajectory

This confirmed that the controller provides a FollowJointTrajectory
action server.

An action is useful when a task takes time to complete.

For example:

    "Move the robot to this position over 3 seconds."

An action can provide:

    Goal
    Feedback
    Result
    Success/failure status


============================================================
FOLLOWJOINTTRAJECTORY
============================================================

The action type is:

    control_msgs/action/FollowJointTrajectory

A trajectory contains:

    joint names
    target positions
    timing

Example target:

    shoulder_pan_joint   = 0.3
    shoulder_lift_joint  = -1.57
    elbow_joint          = 0.0
    wrist_1_joint        = -1.57
    wrist_2_joint        = 0.0
    wrist_3_joint        = 0.0

The robot was commanded to reach this configuration after:

    3 seconds

FIRST DIRECT TERMINAL MOVEMENT TEST
============================================================

============================================================
PYTHON ROS 2 CONCEPTS USED
============================================================

The Python program imports:

    import rclpy
    from rclpy.node import Node
    from rclpy.action import ActionClient

    from control_msgs.action import FollowJointTrajectory
    from trajectory_msgs.msg import JointTrajectoryPoint


Node:
A ROS 2 program is commonly represented as a Node.

Our node is:

    ur5e_controller


ActionClient:
The Python program uses an ActionClient to communicate with the
FollowJointTrajectory action server.

The client connects to:

    /scaled_joint_trajectory_controller/follow_joint_trajectory


FollowJointTrajectory.Goal:
Represents the movement request.

JointTrajectoryPoint:
Represents a point in the robot trajectory.

The point contains the desired joint positions and timing.

============================================================
KEY ROS 2 TERMS TO UNDERSTAND
============================================================

NODE
----
A running ROS 2 program.

Example:

    ur5e_controller


TOPIC
-----
A communication channel used for continuous data.

Example:

    /joint_states


PUBLISHER
---------
A ROS 2 node that sends messages to a topic.


SUBSCRIBER
----------
A ROS 2 node that receives messages from a topic.


SERVICE
-------
Used for request/response communication.


ACTION
------
Used for longer-running tasks.

Example:

    FollowJointTrajectory


ACTION SERVER
-------------
The component that receives and executes an action goal.

Our action server:

    /scaled_joint_trajectory_controller


ACTION CLIENT
-------------
The component that sends goals to an action server.

Our Python program uses:

    ActionClient


ROS2_CONTROL
------------
Framework for controlling robot hardware or simulated robot hardware.


CONTROLLER
----------
A component that accepts commands and converts them into appropriate
robot control operations.

Our controller:

    scaled_joint_trajectory_controller


JOINT STATE
-----------
Information about the current state of a robot joint.

Includes:

    position
    velocity
    effort


TRAJECTORY
----------
A sequence of desired robot states over time.


WAYPOINT
--------
A specific point in a trajectory.

We currently have only one waypoint.

The next stage is to use multiple waypoints.
